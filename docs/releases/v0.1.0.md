# RepoPilot v0.1.0 — Developer Preview

This is a local-first developer preview, not a production or hosted release. It packages the CLI as a
self-contained Node.js archive. The web dashboard remains a source-checkout development shell and is
not included in the CLI archive.

## Install

Requirements: Node.js 22–25 and Git. For pnpm-based target projects, install pnpm 11 separately.
Download `repopilot-0.1.0.tgz` and `repopilot-0.1.0.sha256` from this release, verify the checksum,
then install:

```bash
shasum -a 256 -c repopilot-0.1.0.sha256
npm install -g ./repopilot-0.1.0.tgz
repopilot version
repopilot doctor
```

On Linux, `sha256sum -c repopilot-0.1.0.sha256` is an alternative checksum command. To upgrade,
install a newer release archive the same way. To remove the CLI, run `npm uninstall -g repopilot`.
The local `.repopilot/` configuration and run journals in repositories are not removed by uninstall.

## What works

- Evidence-backed repository scanning and versioned policy inspection.
- Durable read-only planning with the deterministic fake provider or a configured loopback Ollama
  model.
- Bounded source-context selection in a separate process for Ollama change proposals.
- Strict proposal validation and isolated Git-worktree apply; the primary checkout is unchanged.
- Explicitly approved, no-shell validation commands and policy-bounded manual repair proposals.

For Ollama, install and start Ollama and an appropriate coding model separately, then configure the
model for each target repository:

```bash
repopilot providers configure ollama --model <installed-model> --repo <repository>
repopilot providers doctor --repo <repository>
repopilot run "Add parser coverage" --provider ollama --repo <repository> --json
repopilot propose <run-id> --repo <repository> --json
repopilot inspect <run-id> --repo <repository> --json
repopilot apply <run-id> --approve --repo <repository> --json
```

The apply result gives the isolated worktree path. Install dependencies there yourself before
`repopilot verify <run-id> --execute-checks --repo <repository>`; RepoPilot does not install target
dependencies automatically. Review the proposal and understand the target repository before opting
into validation, because its build and test tools may execute untrusted code.

## Known limits

- Ollama was tested with injected HTTP fixtures; this release was not tested against a live model.
- Standalone Codex authentication and SDK/App Server transport are not configured yet. The injected
  Codex provider contract remains available to embedders.
- No automatic commit, push, pull request, worktree cleanup, interactive approvals, or cloud-hosted
  execution is included.
- The command catalog currently targets Node/pnpm tooling. Other ecosystems need additional trusted
  validation definitions.
- The source-context broker is a process boundary, not an OS sandbox. The user must review model
  output and keep repository execution policy conservative.
