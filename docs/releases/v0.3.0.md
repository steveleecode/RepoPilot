# RepoPilot v0.3.0 — Guided Development Preview

This release focuses on a clearer local CLI workflow. It adds guided project setup, selectable Codex
specialist agents, optional Gemini chat and agent tailoring, evidence-based GitHub CI generation, and
shorter command entry points. It remains a developer preview: model output and target-repository
checks require human judgment.

## Install or upgrade

Requires Node.js 22–25 and Git. Download `repopilot-0.3.0.tgz` and its `.sha256` file from the GitHub
release, then:

```bash
shasum -a 256 -c repopilot-0.3.0.sha256
npm install -g ./repopilot-0.3.0.tgz
repopilot version
repopilot doctor
```

Installing the new archive replaces an older global RepoPilot installation. It does not rewrite
existing `.repopilot/config.yaml` policy files or remove local run journals. To uninstall, run
`npm uninstall -g repopilot`.

## Start with a project

```bash
repopilot setup --repo /path/to/project
repopilot scan --repo /path/to/project
repopilot config status --repo /path/to/project
repopilot codex prompt "Add a search filter" --repo /path/to/project
```

In a terminal, setup lets you choose default and optional Codex agents, optionally save a Gemini
key, and optionally ask Gemini to tailor selected roles. The key stays in the project's ignored,
owner-only `.repopilot/.env`; it is not bundled in the release. Gemini receives selected default
agent TOML and an optional description only when AI tailoring is accepted. The generated project
`AGENTS.md` describes the eight-stage workflow and a clarification path: specialists ask the main
agent, which asks the user for decisions that materially affect the work. Existing files are never
overwritten.

If a GitHub remote and supported root package checks are detected, setup proposes a CI workflow at
`.github/workflows/repopilot-ci.yml`. Review it and enable the `validate` job as a required check in
GitHub branch protection or a ruleset. RepoPilot does not change remote GitHub settings.

For scripted setup, use `--agents researcher,developer,tester` and optionally
`--description "React dashboard" --ai --yes`. Run `repopilot help setup` for more.

## Development workflow

```bash
repopilot providers codex login
repopilot plan "Improve parser coverage" --provider codex --repo /path/to/project
repopilot propose <run-id> --repo /path/to/project
repopilot inspect <run-id> --repo /path/to/project
repopilot apply <run-id> --approve --repo /path/to/project
repopilot verify <run-id> --execute-checks --repo /path/to/project
```

`plan` is a clearer alias for the existing provider-backed `run <objective>` command. Planning is
read-only. `apply` uses an isolated worktree; `verify` can execute target-project scripts and should
be used only with a trusted repository. No command silently pushes, merges, or deploys.

## Limits

- Gemini chat and tailoring need a user-provided Gemini API key and network access. Free-tier
  availability and limits depend on the user's Google project.
- Codex planning needs a separately installed and authenticated Codex CLI. Ollama remains available
  as a local provider.
- The generated CI workflow supports root npm or pnpm lockfiles and scripts; review its Node version,
  default branch, and commands before committing.
- Configuration migration is not automatic in this version. Policy config still uses schema
  `version: 1`.
