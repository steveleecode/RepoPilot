# RepoPilot v0.2.0 — Codex Developer Preview

This release adds a complete Codex-backed local workflow alongside Ollama. It is a developer preview,
not a hosted service or an unattended code-writing agent. RepoPilot owns proposal validation and
isolated-worktree application; Codex never writes to the primary checkout through this workflow.

## Install

Requirements: Node.js 22–25 and Git. For the Codex provider, install the Codex CLI separately and
sign in with ChatGPT or an OpenAI API key. Codex manages its own credentials; RepoPilot does not
store or package them. Download the `.tgz` and `.sha256` assets from this release, then:

```bash
shasum -a 256 -c repopilot-0.2.0.sha256
npm install -g ./repopilot-0.2.0.tgz
repopilot version
repopilot doctor
repopilot providers codex login
repopilot providers doctor
```

Use `repopilot providers codex login --device-code` if browser callback login is unavailable. An
existing `codex login` is reused. API-key login can be performed with the Codex CLI's
`codex login --with-api-key` command; never pass a key on a command line or store it in a repository.
See the [official OpenAI authentication guide](https://learn.chatgpt.com/docs/auth) for the two
sign-in methods and their billing differences.

## Codex workflow

```bash
repopilot run "Improve parser coverage" --provider codex --repo <repository> --json
repopilot propose <run-id> --repo <repository> --json
repopilot inspect <run-id> --repo <repository> --json
repopilot apply <run-id> --approve --repo <repository> --json
repopilot verify <run-id> --execute-checks --repo <repository> --json
```

Planning uses repository metadata only. For change proposals, a separate context broker selects
bounded, non-secret source files and sends that context to Codex. The Codex turn runs in a temporary
directory with a read-only sandbox. RepoPilot validates the resulting structured proposal and applies
it only after explicit approval to a detached Git worktree. Inspect the proposal before applying it.
Install target-project dependencies in the worktree yourself before validation. Validation commands
may execute target code and require the explicit `--execute-checks` flag.

Ollama remains available using the v0.1.0 configuration and workflow. To upgrade, install the new
archive with `npm install -g` as above. To uninstall, run `npm uninstall -g repopilot`.

## Limits

- Codex CLI and network access are required for Codex-backed planning and proposals. Availability,
  model access, and usage limits depend on the user's Codex sign-in.
- RepoPilot does not automatically commit, push, create pull requests, or clean up worktrees.
- The context broker is a process boundary, not an OS sandbox; review model output and keep policy
  conservative. Codex's own read-only sandbox is an additional boundary.
- Validation command catalog is currently tailored to Node/pnpm projects.
